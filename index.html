04 / PRODUCT DECISION ARTIFACTS

Trade-offs, frameworks & product calls.

Product ownership is defined by making the right calls under tight constraints. Here are three concrete decision frameworks from my lending, payments, and origination work.

PRIORITIZATION FRAMEWORK · RICE MATRIX

SSP Servicing Scope: Instant Docs vs. Digital Foreclosure

Engineering capacity allowed only 2 major epics in Q1. Backlog had: (A) Instant Document Downloads (SOA/RPS), (B) EMI Cycle Date Change, (C) Full Digital Foreclosure, (D) Part-Payment Calculator.

TRADE-OFF & RATIONALE

Instant Documents had 10x higher customer volume (50k/mo) and simple read APIs (RICE Score 850), while Foreclosure had high complexity with penalty recalculations (RICE Score 320). Decision: Shipped Instant Documents in Sprint 1, eliminating 60% of manual branch tickets within 45 days before sequencing foreclosure in Phase 2.

TRANSACTION ARCHITECTURE · STATE MACHINE

GPS Middleware: Timeout Handling & Idempotency Rules

Network latency between GPS and NPCI switches during peak IMPS hours left customer accounts debited with uncertain switch responses.

TRADE-OFF & RATIONALE

Immediate reversal risks double-credit if the switch completes later; waiting for EOD reconciliation causes customer panic. Decision: Enforced strict UUID idempotency at API gateway + built a 3-tier state machine (INITIATED → IN_FLIGHT max 120s → auto-enquiry). If unconfirmed after 3 retries, marked PENDING_REVERSAL with instant SMS and automated 15-minute batch reversal.

FUNNEL ANALYTICS · ROOT CAUSE TRIAGE

LOS Funnel: Tech Latency vs. Risk/Policy Drop-Offs

Partner channels showed 42% abandonment between Sanction Offer and Agreement Execution. Stakeholders initially assumed API latency and server timeouts were causing customer exit.

TRADE-OFF & RATIONALE

Engineering proposed a 3-month API rewrite. Decision: Instrumented step-level event logging separating HTTP 5xx errors from rejection codes. Disproved the tech hypothesis (<0.5% technical failure) and showed 82% of drop-offs were driven by CKYC address mismatch and KFS fee hesitation. Solved via inline OTP verification and fee transparency, saving 3 months of dev effort.

Today's Disbursements: Success, Failure, In-Progress & Drop-Off

Real-time operational dashboard query monitoring today''s loan disbursements across payment rails, aggregating success, failure, in-progress, and drop-offs with amount and count.

SELECT
  DATE(disbursement_initiated_at) AS disbursement_date,
  partner_channel,
  payout_rail, -- IMPS, NEFT, RTGS, IFT
  COUNT(disbursement_id) AS total_initiated,
  COUNT(CASE WHEN status = ''SUCCESS'' THEN 1 END) AS successful_count,
  ROUND(SUM(CASE WHEN status = ''SUCCESS'' THEN disbursement_amount ELSE 0 END) / 10000000.0, 2) AS success_value_cr,
  COUNT(CASE WHEN status = ''FAILED'' THEN 1 END) AS failed_count,
  ROUND(SUM(CASE WHEN status = ''FAILED'' THEN disbursement_amount ELSE 0 END) / 10000000.0, 2) AS failed_value_cr,
  COUNT(CASE WHEN status = ''IN_PROGRESS'' THEN 1 END) AS in_progress_count,
  COUNT(CASE WHEN status = ''DROPPED_OFF'' THEN 1 END) AS dropped_off_before_payout,
  ROUND(100.0 * COUNT(CASE WHEN status = ''SUCCESS'' THEN 1 END) / NULLIF(COUNT(disbursement_id), 0), 2) AS success_rate_pct
FROM los_disbursement_transactions
WHERE disbursement_initiated_at >= CURRENT_DATE
GROUP BY 1, 2, 3
ORDER BY total_initiated DESC;
